# 윤문은 문장만 다듬고 내용과 구조는 그대로 둔다

문서를 다 쓴 뒤 문장을 사람이 쓴 글처럼 다듬는다. 다듬는 것은 문장뿐이다. 스펙은 뒤 문서가 번호와 마커로 가리키는 글이라, 윤문이 헤딩·번호·마커·숫자를 하나라도 바꾸면 그 문서는 쓰지 않는다.

어떤 도구로 윤문하는지는 이 문서에 쓰지 않는다. 도구의 이름·설치·부르는 법은 `polish-tool.md` 한 곳에 있다.

## 대상과 때

- 대상: `requirements.md`·`design.md`·`flow.md`·`tasks.md`
- 거치지 않는 것
    - `brief.md`: 입력의 문장을 한 글자도 바꾸지 않는 사본이다. `product:brief` 는 원본 `requirements.md` 가 윤문을 거치지 않았을 때 원본을 윤문한 뒤 쓴다 (`references/brief-format.md` 「내용은 바꾸지 않는다」)
    - `features/*.feature`·`scenarios.md`: Gherkin 키워드와 단계 문장이 깨진다
    - `kickstart.md`: 마스터의 원문 인용이 바뀌면 안 된다
    - `product:quick`: 파일이 없는 채팅 답이다
    - 공유 문서 경로: 로컬 파일이 아니다
- 때: 스킬이 파일을 다 쓰고 자기 검증(`(작성 중)` 검색, 마커·구조 검증)을 마친 직후. 「답 반영」으로 고친 뒤와 `product:persona-review` 가 고친 뒤에도 다시 거친다
- `polish-tool.md` 「준비 확인」이 `NOT_READY` 면 건너뛰고, 끝맺음에 "윤문을 건너뛰었습니다. `/product:setup` 을 실행하세요" 한 줄을 붙인다. 문서 작성은 막지 않는다

## 순서

- `polish-tool.md` 「준비 확인」을 먼저 한다. `NOT_READY` 면 아래를 하지 않고 「대상과 때」의 한 줄만 붙인다
- `cp {파일} {기능 폴더}/.{파일 이름}.before` 로 원본을 남긴다
- `polish-tool.md` 「부르는 법」대로 부른다. 작업 파일을 둘 폴더는 기능 폴더다. 작업 파일이 product 폴더 안에만 생기게 하려는 것이다
- `polish-tool.md` 「윤문본 꺼내기」로 윤문본 경로를 받는다
- 「덮어쓰기 전 검사」를 하고, 같을 때만 덮어쓴다
- 「윤문한 흔적」을 남긴다

## 건드리지 않을 것

윤문 도구에 그대로 넘긴다.

- 헤딩 줄
- `@` 마커와 괄호 속 출처
- 결정 ID(`A1`·`S2`)와 요구사항 번호
- EARS 키워드(`THE System`·`SHALL`·`WHEN`·`WHILE`·`IF`·`THEN`)
- 표의 행과 열
- 코드 블록과 mermaid, 백틱 안 글자
- 경로, 숫자와 날짜, 체크박스

## 덮어쓰기 전 검사

윤문본이 지켜야 할 것을 원본과 윤문본에서 뽑아 비교한다.

```bash
keep() {
  grep -E '^#' "$1"
  awk '/^```/{f=!f; print; next} f' "$1"
  grep -c '^|' "$1"
  grep -oE '@(결정|해석|초안|미정|사실|가정|확정)|[A-Z][0-9]+|[0-9][0-9,.:+-]*|`[^`]+`|THE System|SHALL|WHEN|WHILE|IF|THEN' "$1" | sort
}
diff <(keep {원본}) <(keep {윤문본}) && echo SAME || echo DIFF
```

- `SAME`: 윤문본으로 원래 파일을 덮어쓴다
- `DIFF`: 원래 파일을 그대로 두고, 끝맺음에 "윤문이 {diff 첫 줄}을 바꿔서 원본을 유지했습니다" 한 줄을 붙인다

## 윤문한 흔적

윤문을 거친 문서인지는 도구의 작업 파일이 아니라 아래 파일 하나로 안다. 도구가 바뀌어도 이 자리는 그대로다.

- 검사가 `SAME` 이든 `DIFF` 든 `mv {기능 폴더}/.{파일 이름}.before {기능 폴더}/_humanize/{파일 이름}.before` 로 옮긴다. 폴더가 없으면 만든다. 다시 윤문하면 덮어쓴다
- `{기능 폴더}/_humanize/{파일 이름}.before` 가 있으면 그 문서는 윤문을 거친 것이다. 윤문 전 원문이기도 하다
- 윤문을 건너뛰었으면(`NOT_READY`, 윤문본을 못 찾음) `.{파일 이름}.before` 를 지우고 흔적을 남기지 않는다
- 작업 파일은 `polish-tool.md` 「작업 파일 치우기」의 "남길 때"로 `{기능 폴더}/_humanize/` 에 모은다. 리포를 더럽히지 않으려는 것이다
