# product:kickstart — 문서와 맥락을 넘겨 새 세션에서 구현 착수

요구사항·설계·구현 계획 문서가 다 있으면 구현은 새 세션에서 시작하는 편이 낫다. 문서를 쓰느라 찬 세션은 구현에 쓸 자리가 적기 때문이다. 이 스킬은 두 가지를 한다.

- 세 문서에 없는 지금 세션의 맥락을 인수인계 문서 `kickstart.md` 로 남긴다
- 그 문서를 물린 새 세션(지휘 세션)을 fable 모델로 백그라운드에 띄운다. 결과는 기다리지 않는다

먼저 `${CLAUDE_PLUGIN_ROOT}/references/spec-format.md` 「저장 위치」와 `${CLAUDE_PLUGIN_ROOT}/references/kickstart.md` 를 읽는다. 인수인계 문서의 모양과 지휘 세션의 역할 규칙은 뒤 문서에 있다. 이 스킬은 "어떤 순서로 넘기는가" 만 정한다.

- `product:task`: 구현 계획 문서(tasks.md). 이 스킬의 입력이다
- 이 스킬은 코드를 바꾸지 않고, 워크트리·브랜치·PR 도 만들지 않는다. 지휘 세션이 리포의 규칙대로 준비한다

## 입력 찾기

- spec-format 「저장 위치」의 「폴더 고르기」로 폴더를 정한다. 파일 경로를 받으면 그 파일이 있는 폴더다. 경로를 받지 않았으면 `product:task` 와 같은 갈래(기능 폴더를 고르게 한다)를 탄다
- 폴더에 `requirements.md`·`design.md`·`tasks.md` 가 **모두** 있어야 한다. 하나라도 없으면 띄우지 않고 빠진 문서와 만드는 명령을 알린다
    - `requirements.md` 가 없다 → `/product:draft {설명}`
    - `design.md` 가 없다 → `/product:design {requirements.md 경로}`
    - `tasks.md` 가 없다 → `/product:task {폴더}`
- `tasks.md` 를 끝까지 읽는다. 작업 DAG 에 `class … todo` 줄이 없거나 그 줄에 노드가 하나도 없으면 띄우지 않고 "남은 작업이 없습니다" 한 줄로 답한다
- 요구사항·설계 문서는 이 세션이 이미 읽었으면 다시 읽지 않는다. 읽은 적이 없으면 「필요한 결정」 절만 읽어 열린 결정이 남았는지 본다. 남았으면 인수인계 문서 「확인 필요」에 결정 ID 를 적는다

## 인수인계 문서 쓰기

- `references/kickstart.md` 「문서 구성」대로 기능 폴더의 `kickstart.md` 를 쓴다
- 세 문서에 이미 있는 것은 옮겨 적지 않는다. 이 세션에만 있는 것을 적는다: 마스터가 채팅에서 말한 제약과 지시(원문 그대로), 문서에 반영되지 않은 결정과 버린 대안과 그 이유, 직접 돌려 본 명령과 결과, 확정하지 못한 것
- 이 세션에 넘길 맥락이 없으면(새로 연 세션에서 부른 경우) 그 절에 "없음" 을 적는다. 절을 지우지 않는다
- `kickstart.md` 가 이미 있으면 읽고, 「진행 기록」과 앞선 맥락을 그대로 둔 채 이번 세션의 맥락을 덧붙인다
- 윤문을 거치지 않는다. 마스터의 원문 인용이 바뀌면 안 되기 때문이다

## 새 세션 띄우기

아래 명령을 실행한다. `{…}` 자리만 채운다.

```bash
(cd "{지금 세션의 작업 폴더 절대경로}" && claude --bg --model fable \
  --name "kickstart-{기능 폴더 이름의 _ 를 - 로 바꾼 것}" \
  "@{kickstart.md 절대경로} 이 인수인계 문서를 읽고 구현에 착수해라. 문서 「읽을 문서」의 세 문서를 먼저 끝까지 읽는다. 너는 지휘 세션이다. 문서 「역할」대로 지시와 검수만 하고, 코드 수정과 커밋은 서브에이전트에 맡긴다. 문서 「완수조건」이 기준이다.")
```

- 모델은 `fable` 로 고정한다. 지금 세션의 모델을 따라가지 않는다
- 프롬프트는 위 고정 문장만 쓴다. 마스터의 추가 지시는 프롬프트에 넣지 않고 인수인계 문서 「마스터의 제약과 지시」에 원문으로 적는다. 따옴표나 `$` 가 섞인 문장이 셸에서 깨지지 않게 하기 위해서다
- `--name` 에는 숫자·영문·`-` 만 쓴다. 기능 폴더 이름에 그 밖의 글자(예전 한국어 폴더 이름)가 있으면 `kickstart` 만 쓴다
- 프롬프트는 맨 끝에 그대로 준다. `--print` 는 `--bg` 와 함께 쓰지 못한다
- `@` 뒤 파일은 절대경로로 준다
- 세션은 명령을 실행한 폴더에서 뜬다. 그래서 `cd` 를 함께 묶는다
- 출력이 `Workspace not trusted` 면 세션이 뜨지 않은 것이다. 다시 시도하지 않고 "이 폴더에서 `claude` 를 한 번 열어 신뢰 질문에 답한 뒤 `/product:kickstart {폴더}` 를 다시 부르세요" 한 줄로 답한다. 신뢰는 git 리포(워크트리)마다 따로 받는다
- 출력의 `backgrounded · {잡 id}` 에서 잡 id 를 읽는다. 잡 id 가 없으면 출력 마지막 줄을 그대로 알리고, 마스터가 직접 실행할 수 있게 위 명령을 채운 채로 답에 붙인다

Claude Code 2.1.332 에서 확인한 것: 위 모양의 명령이 Fable 5.2 로 뜨고, `@` 절대경로 파일을 읽는다. 신뢰받지 않은 폴더에서는 `Workspace not trusted` 로 끝나고 세션이 뜨지 않는다. 그보다 낮은 버전에서는 확인하지 않았다.

## 끝맺음

띄웠으면 이 세션의 일은 끝이다. 결과를 기다리지 않는다.

- 첫 줄: 진행을 보는 명령 `claude attach {잡 id}` (출력만 보려면 `claude logs {잡 id}`)
- 둘째 줄: 인수인계 문서 경로(클릭 가능한 `path`)와 지휘 세션이 먼저 시작할 작업 ID
- 「확인 필요」에 남긴 것이 있으면 그 목록. 마스터가 지금 답할 수 있는 것일 수 있다
- `mode` 가 `internal` 이면 "`kickstart.md` 는 세션 사이 메모라 커밋하지 않습니다. `.gitignore` 에 `kickstart.md` 를 더할까요?" 한 줄

## 하지 않는 것

- 코드를 바꾸지 않는다
- 워크트리·브랜치·PR 을 만들지 않는다
- 요구사항·설계·구현 계획 문서를 고치지 않는다
- 세 문서의 규칙·수치를 `kickstart.md` 에 옮겨 적지 않는다
- 새 세션의 결과를 기다리지 않는다
