# product:brief — 사람이 읽을 곳을 앞에 모은 기획 문서

요구사항 문서를 받아 마커를 지우고, 사람이 읽을 내용을 앞에 모으고, 한 장으로 묶은 사본을 쓴다. 읽는 사람이 결정 표기 없이, 다른 파일을 열지 않고, `# LLM 맥락용` 제목 앞까지만 읽으면 되게 하는 것이 목적이다. 코드는 바꾸지 않는다.

먼저 `${CLAUDE_PLUGIN_ROOT}/references/brief-format.md` 를 읽는다. 입력과 출력, 「변환 원칙」, 「절 순서」, 「한 장으로 묶기」, 「날짜와 회의 출처」, 「마커 제거」, 「답 반영」은 그 문서를 따른다.

- `product:draft`: 이 스킬의 입력(requirements.md)을 쓴다

## 내용은 절대 고치지 않는다

이 스킬에서 가장 먼저 지키는 규칙이다. 자세한 것은 `brief-format.md` 「내용은 바꾸지 않는다」에 있다.

- 입력에 있던 문장, 표, 불릿, 숫자, 예시, 그림은 적힌 글자 그대로 옮긴다. 자리만 바꾼다
- 바꿔 쓰지 않는다. 줄이지 않는다. 요약하지 않는다. 쉬운 말로 풀지 않는다
- 사람이 읽지 않아도 되는 내용은 지우지 않고 `# LLM 맥락용` 아래로 옮긴다
- 글자가 바뀌는 곳은 `brief-format.md` 가 정한 것뿐이다: 마커와 표기 열, 괄호 속 날짜·회의 출처, 링크와 로컬 파일 경로, 링크가 끊겨 어색해진 문장의 최소한의 고침, 「절 순서」의 「더하는 줄」, 「참여자별 검토 기록」 절
- `brief.md` 는 윤문하지 않는다. 윤문은 원본인 `requirements.md` 가 거친다 (「쓰는 순서」의 원본 윤문 확인)
- 고치고 싶은 문장이 보이면 brief 에서 고치지 않고 끝맺음에 "requirements.md 에서 고칠 후보" 로 적는다

## 입력 찾기

- 설명에 경로가 있으면 그 `requirements.md`. 폴더면 그 안의 `requirements.md`
- 없으면 `spec-format.md` 「저장 위치」의 「폴더 고르기」로 폴더를 고른다. 폴더가 하나도 없거나 고른 폴더에 `requirements.md` 가 없으면 쓰지 않고 "`/product:draft` 를 먼저 실행하세요" 한 줄을 남긴다
- 입력에 `(작성 중)` 이 남아 있으면 쓰지 않고, 그 절 이름을 알려 준다
- 설명에 "artifact", "아티팩트" 가 있으면 「공유 문서 경로」, 없으면 마크다운으로 쓴다

## 쓰는 순서

- 입력을 끝까지 읽는다. 앞부분만 보고 쓰지 않는다
- 원본 윤문 확인: `requirements.md` 가 윤문을 거쳤는지 본다. `product:draft` 가 다 쓴 뒤 윤문하므로 보통은 거친 문서다
    - 거쳤다고 보는 때: `{입력 폴더}/_humanize/*/01_input.txt` 가운데 첫 줄이 `requirements.md` 의 첫 줄(제목)과 같은 것이 있다. `head -n 1` 으로 견준다
    - 없으면 거치지 않은 문서다(윤문 플러그인이 없어 건너뛰었거나 손으로 쓴 문서). brief 를 쓰기 전에 `requirements.md` 를 spec-format 「윤문」대로 윤문한다. 덮어썼으면 입력을 다시 읽는다
    - 윤문 플러그인이 없거나 「덮어쓰기 전 검사」가 `DIFF` 여서 원본이 그대로면, 멈추지 않고 그 원본으로 brief 를 쓴다. 끝맺음에 spec-format 이 정한 한 줄을 붙인다
    - 입력이 공유 문서면 이 단계를 건너뛴다
- 「한 장으로 묶기」의 「바깥 참조 찾기」로 바깥 참조를 찾는다. 링크한 용어 파일, 문서 지도, 출처 문서의 `brief.md`(없으면 `requirements.md`)를 읽는다. 바깥 참조가 없으면 이 단계를 건너뛴다
- 채팅에 "{입력 폴더}/brief.md 에 씁니다" 한 줄을 남긴다
- 「절 순서」대로 절과 블록을 놓고, 「한 장으로 묶기」, 「날짜와 회의 출처」, 「마커 제거」를 적용해 Write 로 한 번에 쓴다. 풀어 쓴 뜻과 맨 끝 절에도 같은 규칙을 적용한다
- 검증한다. 하나라도 걸리면 고치고 다시 검증한다
    - 마커: `grep -nE '@(결정|해석|초안|미정|사실|가정|확정)' brief.md` 결과가 없다
    - 표기 열: `grep -n '표기 |' brief.md` 결과가 없다
    - 링크: `grep -nE '\]\(<?\.\./|\.md>?\)' brief.md` 결과가 없다
    - 경계: `` awk '/^```/{f=!f} !f && /^(---|# LLM 맥락용)$/' brief.md `` 결과가 `---`, `# LLM 맥락용` 두 줄이고 이 순서다
    - 앞쪽: `` awk '/^```/{f=!f} !f && /^---$/{exit} !f && /^## /' brief.md `` 에 「정해진 원칙」, 「지금 동작」, 「결정 기록」, 「기존 시스템과 맞닿는 곳」, 「다른 문서에서 가져온 내용」이 없다. `` awk '/^```/{f=!f} !f && /^---$/{exit} 1' brief.md | grep -nE '^\*\*(지금 동작|정해진 원칙)' `` 결과가 없다
    - 구조: `` awk '/^```/{f=!f} !f && /^#{1,3} /' `` 로 뽑은 헤딩을 정렬해 두 문서를 비교한다. 입력에서 「참여자별 검토 기록」을 빼고, brief 에서 「다른 문서에서 가져온 내용」과 「더하는 줄」의 헤딩(`# LLM 맥락용`, `## 구현 전에 확인할 것`, `## 정해진 원칙`, `## 지금 동작`, `### 지금 동작: 요구사항 {n}`)을 빼면 같다
    - 요구사항: `grep -c '^### 요구사항 '` 가 입력과 같다
    - 번호: `grep -c '^[0-9]\+\. '` 가 입력과 같다
    - 지금 동작: `grep -c '^\*\*지금 동작\*\*'` 가 입력과 같고, `grep -c '^### 지금 동작: 요구사항 '` 와도 같다
    - 내용: 입력에 지우는 규칙을 적용한 줄과 brief 의 줄을 정렬해 비교한다. brief 에만 있는 줄은 「더하는 줄」, 풀어 쓴 용어 뜻, 「다른 문서에서 가져온 내용」 절뿐이고, 입력에만 있는 줄은 「참여자별 검토 기록」 절과 헤딩으로 올린 굵은 제목 줄뿐이다. 그 밖의 차이가 있으면 문장을 고친 것이니 입력의 글자로 되돌린다
    - 가져오기: 입력에 다른 문서의 요구사항 번호나 「결정 기록」에 없는 결정 ID 가 있었으면, 그것들이 모두 맨 끝 절에 있다

## 공유 문서 경로

입력이 공유 문서 링크이거나 설명에 아티팩트 요청이 있을 때만 쓴다.

- 입력 문서를 읽는 도구와 새 문서를 만드는 도구는 `product:draft` 「공유 문서 경로」를 따른다
- 내용은 마크다운 경로와 같다. 공유 문서는 표를 그려 주므로 표를 그대로 둔다
- 다 만들면 문서 링크를 끝맺음 둘째 줄에 둔다

## 끝맺음

- 첫 줄: 다음 행동 하나
    - 열린 결정이 있으면: 다음에 답할 결정 하나와 추천안. 답은 `requirements.md` 에 반영된다고 붙인다
    - 없으면: 문서를 열어 `# LLM 맥락용` 앞까지 읽으라는 한 줄
- 둘째 줄: 문서 경로(클릭 가능한 `path`) 또는 링크
- 무엇을 지우거나 옮겼는지 불릿 5개 이하 (예: 마커 N개, 표기 열 N개, LLM 맥락용으로 옮긴 블록 N개, 풀어 쓴 용어 N개, 가져온 요구사항 N개·결정 N개). 문서 내용을 채팅에 다시 늘어놓지 않는다
- 「한 장으로 묶기」에서 찾지 못한 번호나 정의를 넣을 후보가 있으면 그 이름
- requirements.md 에서 고칠 후보가 있으면 그 자리
- 원본 윤문 확인에서 `requirements.md` 를 윤문했으면 그 사실 한 줄

## 하지 않는 것

- 코드를 바꾸지 않는다
- 입력에 있던 내용을 고치지 않는다 (「내용은 절대 고치지 않는다」)
- 조사하지 않는다. 결정·절·예시·그림을 더하지 않는다. 풀어 쓴 뜻과 「다른 문서에서 가져온 내용」은 바깥 문서에 있는 것을 옮길 뿐이다
- 옮긴 글 안의 번호를 다시 따라가지 않는다. 한 단계만 가져온다
- `brief.md` 를 윤문하지 않는다. 윤문이 필요하면 `requirements.md` 를 윤문하고 다시 만든다
- 마스터 답을 brief.md 에 반영하지 않는다. `requirements.md` 에 반영하고 다시 만든다
