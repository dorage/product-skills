# 발표 자료 PDF 만들기

읽는 사람이 첫 두 쪽과 하이라이트만 읽어도 결론과 요청을 알 수 있는 가로 16:9 발표 자료를 만든다.

## 적용하는 원칙

원칙의 내용은 `${CLAUDE_PLUGIN_ROOT}/principles/` 의 문서에만 있다. 일을 시작하기 전에 아래 문서를 모두 읽고, 이 문서에는 원칙의 내용을 다시 쓰지 않는다.

`[[이름]]` 은 `${CLAUDE_PLUGIN_ROOT}/principles/{이름}.md` 를 가리킨다. 다른 폴더에서 같은 이름의 파일을 찾지 않는다.

이 문서의 `${CLAUDE_PLUGIN_ROOT}` 가 경로로 바뀌지 않고 글자 그대로 보이면, 이 스킬 폴더(`SKILL.md` 가 든 폴더)의 두 단계 위 폴더 경로로 바꿔 넣는다. 아래 템플릿과 검사 스크립트 경로도 같다.

## 착수 전 확인

아래 네 가지 중 설명에서 알 수 없는 것만 한 번에 묻는다. 알 수 있는 것은 묻지 않고 뼈대에 적어 보여 준다.

- 읽는 사람이 누구이고, 다 읽은 뒤 무엇을 정해 주기를 바라는가
- 근거로 쓸 자료(파일, 붙여 준 글)가 무엇인가
- 자료에 적지 않고 말로 할 내용이 있는가
- 보여 줄 자료와 따로, 마스터만 보는 메모가 필요한가

근거 자료는 끝까지 읽는다. PDF 는 쪽 범위를 나눠 전부 읽는다.

## 뼈대 먼저

파일을 만들기 전에 아래 표를 채팅으로 보여 주고 승인을 받는다. 뼈대의 문장은 보여 주기 전에 [[polish-without-mark]] 대로 윤문한다. 이 표가 발표 자료의 설계도이고, 하이라이트 문장은 이 표에 적힌 것이 전부다.

| 쪽 | 층 | 하이라이트 문장 | 아래에 두는 세부 | 근거 출처 |
| --- | --- | --- | --- | --- |
| 1 | 표지 | … | 날짜, 작성자 | |
| 2 | 결론 | ① … ② … ③ … | 문장마다 근거 쪽 범위 | |
| 3 | 묶음 가 | … | 표 | 자료 이름과 쪽 |

- 층은 표지, 결론, 묶음(가·나·다), 정해 주실 것 순서다
- 표 아래에 "자료에 넣지 않을 말" 목록과 색 세 가지를 적는다
- 자료에 넣을 숫자는 표 아래에 "숫자, 어떻게 구했는가(출처·계산식·가정), 쓰는 쪽" 표로 모아 보여 준다. 마스터가 확인한 숫자만 자료에 넣는다
- 마스터가 말하지 않아서 LLM 이 채운 문장은 표 아래에 따로 모아 적는다
- 뼈대를 고쳐 달라는 답이 오면 표 전체를 다시 낸다

## 만들기

- `${CLAUDE_PLUGIN_ROOT}/skills/presentation/assets/template.html` 을 결과물 폴더에 `{발표 자료 이름}.html` 로 복사한다. 결과물 폴더는 마스터가 정한 곳, 없으면 지금 작업 폴더다
- 템플릿의 쪽 견본(표지, 결론, 두 칸, 표, 흐름과 인용, 정해 주실 것)을 골라 뼈대 표대로 채운다. 쓰지 않는 견본은 지운다
- 색은 `:root` 의 `--bg`, `--ink`, `--hl` 세 값만 바꾼다
- 하이라이트는 `class="hl"` 하나로만 건다

PDF 로 바꾼다.

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu \
  --no-pdf-header-footer --print-to-pdf="$PWD/{발표 자료 이름}.pdf" "file://$PWD/{발표 자료 이름}.html"
```

## 검사

```bash
npx tsx "${CLAUDE_PLUGIN_ROOT}/skills/presentation/scripts/check.ts" "{발표 자료 이름}.html" "{발표 자료 이름}.pdf" --ban "넣지,않을,말"
```

- `--ban` 에는 뼈대의 "자료에 넣지 않을 말"과 `humanize` 를 넣는다
- 스크립트는 쪽 수, 쪽 크기, 색 개수, 쪽별 하이라이트 개수, 넣지 않을 말의 검색 건수를 세고, 하이라이트 문장을 쪽 순서대로 뽑아 보여 준다. 하나라도 어긋나면 끝 코드 1 로 끝난다
- `tsx` 를 받을 수 없으면 `node "${CLAUDE_PLUGIN_ROOT}/skills/presentation/scripts/check.ts" …` 로 돌린다 (Node 24 이상)
- 스크립트가 못 하는 검사 세 가지는 직접 한다: 뽑힌 하이라이트만 읽어 보기, 인용문과 쪽 번호를 원문과 대조하기, PDF 전 쪽을 그림으로 열어 보기
- 고친 뒤에는 PDF 를 다시 뽑고 검사 전체를 다시 돌린다

## 마스터만 보는 메모

착수 전 확인에서 필요하다고 한 때만 만든다.

- 발표 자료와 다른 파일(`{이름} 메모.md`)로 만든다
- 숫자마다 출처를 붙이고, LLM 이 직접 확인하지 않은 출처는 그렇게 적는다

## 공개 범위

급여, 인사, 징계, 계약처럼 민감한 내용이면 로컬 파일로만 둔다. 마스터가 요청하기 전에는 온라인 공유 페이지로 올리지 않는다.

## 끝맺음

- 첫 줄: PDF 의 전체 경로와 먼저 볼 쪽
- 검사 결과를 숫자로 적는다
- 뼈대와 달라진 곳이 있으면 전과 후를 나란히 적는다
- 윤문을 했는지 건너뛰었는지 한 줄로 적는다. 자료에는 적지 않는다
- LLM 이 채운 문장과, 직접 확인하지 못한 근거를 적는다
- 마지막 줄: 마스터가 확인할 것 하나
