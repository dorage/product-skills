# 문장은 윤문하되 윤문 기록은 자료에 적지 않는다

발표 자료는 읽는 사람이 문장만 보고 판단한다. 기계가 쓴 티가 나는 문장은 내용보다 먼저 눈에 걸리므로 다듬는다. 어떤 도구로 다듬었는지는 읽는 사람이 정할 일과 상관없으므로 자료에 적지 않는다.

윤문하는 때

- 뼈대를 보여 주기 전에 한 번 한다. 뼈대의 하이라이트 문장과 세부 문장을 글 파일 하나에 모아 윤문하고, 다듬은 문장으로 뼈대를 보여 준다
- 마스터가 승인한 문장은 다시 윤문하지 않는다. 승인 뒤에 문장이 바뀌면 승인한 것과 다른 자료가 된다
- 만들기 단계에서 새로 쓴 문장이 있으면 HTML 에 넣기 전에 같은 방법으로 윤문하고, 끝맺음의 "뼈대와 달라진 곳"에 적는다

윤문하는 법

- `humanize-korean@im-not-ai` 플러그인을 쓴다. `Skill(skill="humanize-korean:humanize-korean")` 에 글 파일 경로, 강도 "가볍게", 장르 `report` 를 넘긴다
- 건드리지 않을 것으로 숫자와 단위, 날짜, 출처와 쪽 번호, 따옴표 안 인용문, 사람·회사·제품 이름, "추정" 표시를 넘긴다
- 윤문 전과 후의 숫자·인용문 목록이 같은지 견준다. 다르면 그 문장은 원래 문장을 쓴다
- 글 파일과 윤문 작업 폴더(`_workspace/`)는 결과물 폴더에 남기지 않는다. 다 쓰면 지운다
- 플러그인이 없으면 건너뛰고, 자료는 그대로 만든다

적지 않는 것

- HTML 과 PDF 어디에도 윤문 여부, 윤문 도구의 이름, 버전을 적지 않는다. 표지, 꼬리말, 주석, 파일 이름 모두 같다
- 검사할 때 "넣지 않을 말"에 `humanize` 를 더해 0건인지 확인한다
- 윤문했는지와 건너뛰었는지는 채팅의 끝맺음에만 한 줄로 알린다
