# 원칙 문서

report 플러그인의 글과 자료를 만드는 스킬들이 함께 쓰는 원칙이다. 원칙 하나가 문서 하나이고, 스킬은 자기에게 맞는 문서만 골라 `SKILL.md` 의 「적용하는 원칙」 표에 적는다.

## 문서 모양

```markdown
# {원칙}

{설명과 예시}
```

- 길이는 화면 한 장을 넘기지 않는다
- 원칙의 내용은 이 폴더에만 쓴다. 스킬 문서는 파일 이름으로 가리키기만 한다
- 새 원칙은 새 파일로 더하고, 아래 목록에 한 줄을 더한다

## 목록

내용에 관한 원칙

- `conclusion-first.md` 결론을 먼저 놓는다
- `non-overlapping-evidence.md` 근거는 겹치지 않게 묶는다
- `details-below.md` 세부는 아래로 내린다
- `cite-source-and-page.md` 숫자와 인용에는 출처와 쪽 번호를 붙인다
- `evidence-reader-trusts.md` 읽는 사람이 이미 믿는 자료에서 근거를 가져온다
- `facts-not-judgment.md` 사람을 평가하지 않고 일과 사실을 적는다
- `written-vs-spoken.md` 문서에 쓸 것과 말로 할 것을 나눈다
- `decidable-ask.md` 요청은 읽는 사람이 정할 수 있는 항목으로 끝낸다
- `verify-with-numbers.md` 다 만든 뒤 숫자로 검사한다
- `price-the-claim.md` 주장에 값을 매긴다
- `label-estimates.md` 추정은 추정이라고 적고 어떻게 구했는지 댄다
- `progress-not-activity.md` 활동량이 아니라 진척을 보인다
- `readers-words.md` 읽는 사람의 말로 쓴다

쪽 모양에 관한 원칙

- `title-is-claim.md` 쪽 제목은 주제가 아니라 주장이다
- `three-colors.md` 색은 세 가지만 쓴다
- `highlight-limit.md` 하이라이트는 한 쪽에 세 문장까지만 쓴다
- `highlight-only-readable.md` 하이라이트만 읽어도 전체가 이해된다
- `chart-shows-signal.md` 차트는 한눈에 보여야 할 신호가 있을 때만 넣는다

- `report:progress`: `written-vs-spoken.md` 를 뺀 17개. `decidable-ask.md` 는 정해 주실 것이 있을 때만
