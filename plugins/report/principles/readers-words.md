# 읽는 사람의 말로 쓴다

읽는 사람이 모르는 말이 한 쪽에 하나만 있어도 그 쪽의 주장이 전해지지 않는다. 만든 사람이 매일 쓰는 말일수록 읽는 사람에게는 낯설다.

- 뼈대를 짜기 전에 "만든 사람의 말 → 읽는 사람의 말" 표를 만든다. 예: PR → 작업 묶음, 배포 → 운영에 올림, 마이그레이션 → 데이터 구조 변경, 스테이징 → 시험 서버
- 바꾼 말의 원래 말은 "넣지 않을 말" 목록에 넣고, 다 만든 뒤 검색해서 0건인지 본다
- 사람 이름, 계정 이름, 서버 주소처럼 읽는 사람에게 쓸모없고 밖에 나가면 곤란한 값도 같은 목록에 넣는다
- 바꿀 말이 없는 고유한 이름(제품 이름, 기능 이름)은 처음 나올 때 한 줄로 풀어 준다

나쁜 예: "정산 람다 cherry-pick 후 ECS Fargate 전환"

좋은 예: "정산 프로그램 수정을 출시용 코드에 옮기고, 시험 서버를 관리 부담이 적은 방식으로 옮겼습니다"
