# 리포 규칙은 규칙 하나를 문서 하나로 쓴다

이 리포에서 지켜야 할 규칙은 `principles/` 에 규칙 하나당 문서 하나로 쓰고, 어떤 규칙이 있는지는 `PRINCIPLE.md` 에 목록으로 적는다. 규칙을 문서 단위로 떼어 두면 규칙이 서로를 가리키는 관계를 그래프로 그릴 수 있고, 규칙 하나를 고쳤을 때 그 규칙을 가리키는 문서만 세면 어디까지 영향이 가는지 알 수 있다.

## 규칙 하나의 크기

- 규칙 하나는 자기 이유가 따로 있고 다른 규칙과 따로 바뀔 수 있는 덩어리다. 줄 하나가 아니라 이유 하나가 기준이다
- 문서 하나가 이유 두 개를 담게 되면 둘로 나누고, 서로를 [[wiki-link-only]] 대로 가리킨다

## 세 문서가 맡는 일

- `principles/{이름}.md` 는 규칙의 내용을 맡는다. 이유, 자세한 절차, 확인한 사실, 예시는 여기에만 쓴다
- `PRINCIPLE.md` 는 목록만 맡는다. 원칙마다 `[[이름]]` 과 한 문장 설명을 한 줄로 쓴다
- `CLAUDE.md` 는 세션마다 자동으로 읽히는 요약을 맡는다. 규칙마다 `**MUST**`, `**SHOULD**`, `**MUST NOT**`, `**MAY**` 로 시작하는 한 줄을 쓰고 끝에 `[[이름]]` 을 붙인다
- `CLAUDE.md` 의 한 줄은 그 줄만 읽어도 무엇을 해야 하는지 알 수 있게 쓴다. Claude Code 는 `[[이름]]` 을 따라가 읽어 주지 않기 때문이다
- 규칙을 실제로 적용하는 작업을 하기 전에는 그 줄이 가리키는 원칙 문서를 먼저 읽는다

## 문서 모양

```markdown
# {원칙을 한 문장으로}

{왜 이 규칙이 있는지}

- {지킬 것}
```

- 파일 이름은 원칙을 줄인 영어 소문자와 `-` 로 짓는다 (예: `one-rule-one-file.md`)
- 파일 이름은 리포 전체에서 하나뿐이어야 한다. `plugins/{플러그인}/principles/` 의 파일 이름과도 겹치지 않게 짓는다. 이유는 [[wiki-link-only]] 에 있다
- 길이는 화면 한 장을 넘기지 않는다

## 더하거나 고칠 때

- 원칙을 더하거나 빼거나 이름을 바꾸면 같은 커밋에서 `PRINCIPLE.md` 의 줄과 `CLAUDE.md` 의 줄도 고친다
- `principles/` 의 파일과 `PRINCIPLE.md` 의 줄은 하나씩 짝이 맞아야 한다
- 원칙의 내용을 고치기 전에 `grep -rn '\[\[{이름}\]\]' .` 로 그 원칙을 가리키는 문서를 찾고, 고친 내용이 그 문서들과 어긋나지 않는지 본다
- 이름을 바꾸면 위 검색에 나온 모든 `[[이름]]` 을 함께 바꾼다

## 플러그인의 원칙과 다른 점

이 문서는 리포를 고치는 사람과 LLM 이 지키는 규칙을 다룬다. 플러그인의 스킬이 결과물을 만들 때 지키는 원칙은 플러그인 폴더 안에 따로 두고, 그 규칙은 [[skill-principles-in-plugin]] 에 있다.
