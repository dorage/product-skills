# 스킬이 지키는 원칙은 플러그인의 principles 폴더에 모은다

모든 스킬은 자기가 지켜야 할 원칙을 `SKILL.md` 에 풀어 쓰지 않고, 자기 플러그인의 `principles/` 에 정리한다. 원칙이 스킬 문서마다 흩어지면 어떤 원칙이 있는지 한눈에 볼 수 없고, 같은 원칙을 여러 곳에서 고쳐야 한다.

- 원칙의 내용은 `plugins/{플러그인}/principles/` 에만 쓴다. 원칙 하나가 파일 하나이고, 파일 이름은 원칙을 줄인 영어 소문자와 `-` 로 짓는다 (예: `conclusion-first.md`)
- 원칙 문서는 `# {원칙을 한 문장으로}` 제목 아래에 설명과 예시를 쓰고, 길이는 화면 한 장을 넘기지 않는다
- 어떤 원칙이 있는지는 `plugins/{플러그인}/PRINCIPLE.md` 에 적는다. 원칙마다 `[[이름]]` 과 한 문장 요약을 한 줄로 쓴다
- `PRINCIPLE.md` 에는 목록만 둔다. 원칙의 설명과 예시는 원칙 파일에 있다
- 스킬은 `SKILL.md` 에 자기가 지키는 원칙을 `[[이름]]` 으로 가리키기만 하고, 내용을 다시 쓰지 않는다 ([[wiki-link-only]])
- 원칙을 더하거나 빼거나 이름을 바꾸면 같은 커밋에서 `PRINCIPLE.md` 의 줄도 고친다. `principles/` 의 파일과 `PRINCIPLE.md` 의 줄은 하나씩 짝이 맞아야 한다
- 원칙 파일은 플러그인 폴더 안에 둔다. 설치하면 플러그인 폴더만 복사되기 때문이다. 여러 플러그인이 같은 원칙을 쓰면 [[shared-file-by-symlink]] 를 따른다. 링크도 그 플러그인의 `PRINCIPLE.md` 에 한 줄로 적는다

## 설치한 사람의 세션에서 위키 링크가 읽히게 하기

Claude Code 는 `[[이름]]` 을 파일로 바꿔 주지 않는다. 스킬을 읽은 LLM 이 문장을 보고 파일을 찾아 읽는다. 그래서 원칙을 `[[이름]]` 으로 가리키는 `SKILL.md` 에는 아래 두 문장을 반드시 넣는다.

```markdown
`[[이름]]` 은 `${CLAUDE_PLUGIN_ROOT}/principles/{이름}.md` 를 가리킨다. 다른 폴더에서 같은 이름의 파일을 찾지 않는다.
```

- 이 문장이 있으면 LLM 은 파일을 한 번에 연다. 2026-11-28 에 리포 밖 폴더에 둔 시험용 플러그인을 `claude -p --plugin-dir` 로 돌려 확인했다 (opus 5.5, sonnet 5.5)
- 이 문장이 없어도 같은 시험에서 파일을 찾았지만, 플러그인 폴더와 `~/.claude` 를 뒤져서 찾았다. `~/.claude/principles/` 에 같은 이름의 다른 파일이 있으면 그 파일을 읽을 수 있다
- GitHub 마켓플레이스로 설치한 캐시 사본에서는 아직 확인하지 않았다. 경로는 스킬이 템플릿과 스크립트를 찾을 때 이미 쓰는 `${CLAUDE_PLUGIN_ROOT}` 를 그대로 쓴다

리포를 고칠 때 지키는 규칙은 플러그인이 아니라 리포 맨 위에 두고, 그 규칙은 [[one-rule-one-file]] 에 있다.
